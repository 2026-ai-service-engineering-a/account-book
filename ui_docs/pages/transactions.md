# 거래 목록

## 1. 목적

찾고, 확인하고, 고친다. 에이전트가 넣은 기록이 맞는지 사람이 훑어보는 화면이기도 하다.
대화로 "지난주 카페 얼마 썼지"를 물을 수도 있지만, **눈으로 훑고 하나를 골라 고치는 일은
목록이 빠르다.**

## 2. 라우트와 데이터

| | |
|---|---|
| 경로 | `/transactions` |
| 부르는 곳 | `api` — `GET /v1/transactions`, `GET /v1/summary` |
| 필터 상태 | URL 쿼리에 그대로 둔다 (`?period=2026-09&direction=expense`) |

필터를 URL에 두는 이유는 셋이다. 뒤로 가기가 동작한다. 링크로 공유된다. 새로고침해도
같은 화면이 나온다.

## 3. 화면 구조

| 영역 | 내용 |
|---|---|
| 필터 바 | 기간 · 방향 · 카테고리 · 가맹점 검색 |
| 합계 줄 | 지출 합, 수입 합. **순액은 내지 않는다** |
| 목록 | 날짜 내림차순 |
| 더 보기 | 커서 기반. 기본 50건 |

목록 한 줄은 이렇게 생겼다.

> 09-16 · 김밥천국 · `식비` · **-8,500원** · 🤖

| 자리 | 값 | 비고 |
|---|---|---|
| 날짜 | `MM-DD` | 같은 날이 이어지면 첫 줄에만 |
| 가맹점 | `merchant` | 없으면 메모 앞부분 |
| 카테고리 | 배지 | 누르면 그 카테고리로 필터 |
| 금액 | `±` 붙여서 | 지출 `-`, 수입 `+` |
| 출처 | `source=agent`면 표시 | 사람이 넣은 건 표시 없음 |

**출처 표시는 빼지 않는다.** 에이전트가 만든 기록을 언제나 구분할 수 있어야 한다는 건
하네스 규칙이다([../../README.md](../../README.md) 6장).

## 4. 상호작용

| 무엇을 | 무엇이 갱신되나 |
|---|---|
| 필터 변경 | 합계 줄 + 목록. 필터 바 자신은 그대로 |
| 카테고리 배지 클릭 | 같은 위 |
| 더 보기 | 목록 끝에 덧붙인다. 위로 올라가지 않는다 |
| 행 클릭 | [거래 폼](transaction-form.md)으로 이동 |

부분 갱신 대상은 `#summary`와 `#transaction-list` 둘뿐이다. 필터를 바꿀 때마다
URL도 `hx-push-url`로 같이 바꾼다.

**무한 스크롤을 쓰지 않는다.** 스크롤로 저절로 불러오면 사용자가 위치를 잃고, 뒤로
갔다 오면 처음으로 돌아간다. "더 보기"는 누른 사람이 어디 있는지 안다.

## 5. 빈 상태·로딩·에러

빈 화면에는 **두 가지 다른 이유**가 있고, 문구를 다르게 낸다.

| 이유 | 문구 |
|---|---|
| 거래가 하나도 없다 (첫날) | "아직 기록이 없어요. 대화로 넣거나 직접 넣어보세요" + 두 버튼 |
| 필터에 걸리는 게 없다 | "조건에 맞는 거래가 없어요. 필터를 지워볼까요?" + 필터 초기화 |

둘을 같은 문구로 내면 첫날 사용자는 자기가 뭘 잘못한 줄 안다.

**로딩** — 목록 자리에 뼈대(skeleton) 세 줄. 화면이 통째로 깜빡이지 않게 한다.

**에러** — 목록 자리에만 에러를 낸다. 필터 바는 남겨서 조건을 바꿔 다시 시도할 수 있게 한다.

## 6. 결정과 이유

- **합계에 순액을 내지 않는다.** 지출 합과 수입 합을 따로 낸다. 월급이 들어온 달의
  순액은 항상 플러스라서, 그 숫자로는 많이 썼는지 알 수 없다.
- **인라인 편집을 넣지 않는다.** 목록에서 금액을 바로 고치게 하면 확인 절차가 애매해진다.
  고치는 일은 폼에서 한다.
- **기본 기간은 이번 달이다.** 전체를 기본으로 하면 첫 화면부터 느리다.

## 7. 하지 않는 것

- 다중 선택과 일괄 삭제. 되돌릴 수 없는 일을 여러 건 한꺼번에 하게 두지 않는다.
- CSV 내보내기. 가져오기가 먼저다.
- 정렬 바꾸기. 날짜 내림차순 하나로 간다.
