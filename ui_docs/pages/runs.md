# 실행 기록

## 1. 목적

AI가 무엇을 했는지 사람이 거슬러 보는 화면이다. 모든 AI 실행은 감사 로그(`agent_runs`·`tool_calls`)에
남는다([../../docs/ai/README.md](../../docs/ai/README.md) 2장 원칙 7). 그런데 남기기만 하고 볼 길이 없으면
"이 거래는 왜 식비로 들어갔지", "리포트가 무슨 집계를 보고 이 문장을 썼지", "밖의 AI가 무엇을
읽어 갔지"에 답하려면 DB를 열어야 한다. **AI가 한 일을 DB 없이 되짚는 자리**가 이 화면이다.

읽기만 한다. 이 화면에는 쓰기 버튼이 하나도 없다.

## 2. 라우트와 데이터

| | |
|---|---|
| 경로 | `/runs` — 목록, `/runs/{id}` — 실행 하나 |
| 부르는 곳 | `api` — `GET /v1/runs`(목록), `GET /v1/runs/{id}`(실행 하나와 도구 호출) |
| 필터 상태 | URL 쿼리에 그대로 둔다 (`?seat=insight&status=done`) |
| 들어오는 길 | 상단 바 오른쪽 "실행 기록", 그리고 [거래 폼](transaction-form.md)의 "이 기록을 만든 실행" |

`GET /v1/runs`는 최신순 한 쪽과 다음 쪽 커서를 낸다. 한 줄에는 도구 호출 대신 그 **수**만 있다 —
인자와 결과는 펼칠 때 `GET /v1/runs/{id}`로 가져온다. 목록이 무거워지지 않게 하려는 것이다.

`api` 없이 도는 대역에서는 목록이 비어 있다. 각본 대역은 실행을 남기지 않는다
([../stand-ins.md](../stand-ins.md)).

## 3. 화면 구조

| 영역 | 내용 |
|---|---|
| 머리 | 한 줄 설명 — "AI가 한 일을 거슬러 봅니다. 여기서는 아무것도 바꾸지 않습니다." |
| 필터 바 | 자리 · 상태 |
| 목록 | 최신순. 한 줄이 실행 하나 |
| 더 보기 | 커서 기반. 한 쪽 30건 |

목록 한 줄은 이렇게 생겼다.

> 10-15 13:57 · `리포트` · 계획 실행 · **끝남** (assembled) · 도구 4 · 2026-09

| 자리 | 값 | 비고 |
|---|---|---|
| 시각 | `MM-DD HH:MM` | 사용자 타임존 |
| 자리 | 배지 — 기록 · 카테고리 고르기 · 대화 통계 · 문서 Q&A · 리포트 · 외부(MCP) | `seat` |
| 흐름 | 단발 · ReAct · 계획 실행 · 직접 | `flow`. 직접은 LLM 없이 도구 하나(MCP) |
| 상태 | 끝남 · 실패 · 확인 대기 · 취소됨, 괄호 안에 끊긴 이유 | `status`·`stop_reason`. 글자로 낸다 — 색만으로 가르지 않는다 |
| 도구 | 호출 수 | 0이면 "도구 없음" |
| 무엇을 | 발화 앞 40자. MCP는 발화가 없어 클라이언트 이름 | 리포트는 발화 자리에 달(`2026-09`)이 있다 |

**펼친 실행 하나**는 머리 한 줄과 도구 호출 표다.

> 모델 gemini/gemini-flash-lite-latest · 스텝 3 · 토큰 1,240 · $0.000210 · 발화 전문

| 열 | 값 |
|---|---|
| 순서 | 남은 순서 그대로 |
| 도구 | `summarize_spending` |
| 인자 | 요약 — `period=this_month · category_id=food` |
| 결과 | 요약 — `ok · 1줄`, `validation_error — 기간 이름은…`, `category_id=food (history)`, `결과 없음` |
| 확인 | 쓰기 제안만 — 사람이 확인한 시각, 아니면 비어 있다 |
| 원본 | 펼침 안의 펼침 — 인자와 결과의 JSON 그대로 |

결과 요약은 저장된 모양을 따라 넷으로 가른다.

| 저장된 결과 | 요약 |
|---|---|
| 도구 봉투 `{ok, data, meta}` — 대화·리포트·MCP | `ok · N줄`, 잘렸으면 `· 잘림`. 실패면 `코드 — 힌트`. 리포트의 계획 이유(`why`)가 있으면 뒤에 |
| 작은 객체 — 분류·문서·기록 | 값이 하나인 칸을 `키=값`으로. 목록은 `키 N개` |
| `transaction_id`가 있다 | 위와 같이 적고 그 거래로 가는 링크 |
| 없다(`null`) | `결과 없음` — 제안이 대기 중이거나 취소됐다 |

인자 요약은 맨 위 칸을 `키=값`으로 잇는다. 기간은 이름만(`last_n_days`면 `7일`, `month`면 그 달),
그 밖의 객체는 한 줄 JSON이다. 요약은 80자에서 자르고 `…`을 붙인다 — 다 보려면 원본을 연다.

## 4. 상호작용

| 무엇을 | 무엇이 갱신되나 |
|---|---|
| 필터 변경 | 목록(`#run-list`). URL도 `hx-push-url`로 같이 |
| 더 보기 | 목록 끝에 덧붙인다 |
| 행 펼치기 | 그 행의 도구 호출 자리(`#run-{id}-calls`) — 처음 한 번만 가져온다 |
| 원본 펼치기 | 아무것도 가져오지 않는다. 이미 받은 JSON을 연다 |
| 결과의 거래 링크 | [거래 폼](transaction-form.md)으로 이동 |

행은 `<details>`다. 처음 열 때 `hx-trigger="toggle once"`로 도구 호출을 가져와 채우고, 그 뒤로는
브라우저가 접고 편다 — 접기 위해 다시 부르지 않고, 커스텀 JS도 없다. 원본도 `<details>` 안의
`<details>`라 열고 닫는 데 서버가 끼지 않는다.

`/runs/{id}`는 같은 조각을 펼친 채로 담은 한 장이다. 거래 폼에서 오는 링크의 도착점이고,
주소를 남겨 두면 그 실행으로 바로 온다.

## 5. 빈 상태·로딩·에러

| 이유 | 문구 |
|---|---|
| 실행이 하나도 없다 (첫날, 대역) | "아직 AI 실행이 없어요. 채팅에서 물어보거나 기록해 보세요" + 채팅으로 |
| 필터에 걸리는 게 없다 | "조건에 맞는 실행이 없어요. 필터를 지워볼까요?" + 필터 지우기 |
| 실행 하나가 없다 (`/runs/{id}`) | "그 실행을 찾지 못했어요." + 목록으로 — 404 |

**로딩** — 행을 펼친 자리에 "불러오는 중…" 한 줄. 목록은 그대로 둔다.

**에러** — `api`에 닿지 못하면 목록 자리에만 알린다. 필터 바는 남긴다. 펼친 자리에서 실패하면
그 자리에만 "도구 호출을 불러오지 못했어요"를 낸다.

## 6. 결정과 이유

- **쓰기 버튼을 두지 않는다.** 확인 대기인 제안도 여기서 확인하지 않는다 — 확인은 채팅의 카드가
  한다([chat.md](chat.md)). 감사 화면이 상태를 바꾸면 "무엇이 일어났나"를 보는 화면이 그 일의
  일부가 된다.
- **발화와 인자를 화면에 낸다.** 운영 로그에는 넣지 않는 것들이다(development-rules 6.4). 감사 로그는
  사용자 자신의 기록이고, 이 화면은 그 사용자에게만 보인다. 감추면 되짚을 수가 없다.
- **요약이 먼저, 원본은 두 번 열어야 보인다.** 도구 결과 JSON은 한 건이 수 KB다. 펼치자마자 쏟아지면
  훑어볼 수가 없다. 요약은 "무엇을 물었고 무엇이 돌아왔나"까지만 말한다.
- **목록에는 호출 수만 싣는다.** 30건 × 도구 넷 × 수 KB를 첫 화면에 싣지 않는다.
- **행 펼침은 `<details>` + HTMX 한 번.** 접고 펴기를 서버에 묻지 않는다. 다시 열 때 최신이 아닐 수
  있지만, 실행은 끝난 기록이라 거의 바뀌지 않는다 — 대기 중인 제안만 바뀌고, 새로 보려면 새로고침한다.
- **거래와 실행을 양쪽으로 잇는다.** 거래 폼에서 그 거래를 만든 실행으로, 실행의 결과에서 그 거래로.
  "이건 누가 넣었지"(ui-design 2장)의 답이 화면 두 번 누르기로 끝난다.

## 7. 하지 않는 것

- 쓰기 — 확인·취소·다시 실행·지우기.
- 기간 필터와 검색. 자리와 상태 둘로 시작한다.
- 비용 합계와 차트. 실행 단위 비용만 낸다 — 단발 자리는 아직 토큰을 0으로 남긴다(api-contract 6장).
- 자동 새로고침. 실행 중인 것을 따라가는 화면이 아니다.
