# AI 위키

## 1. 목적

이 가계부의 어느 자리에 AI가 들어가고, 거기서 어떤 에이전트 흐름이 도는지를 **화면 안에서**
보여 준다. 설계는 [../../docs/ai/](../../docs/ai/README.md)에 있지만, 화면을 쓰는 사람은 그 문서를
열지 않는다. 화면의 AI 표시를 누르면 그 자리의 설명으로 온다.

정본은 `docs/ai/`다. 위키는 그 요약이고, 둘이 어긋나면 `docs/ai/`를 따른다.

## 2. 라우트와 데이터

| | |
|---|---|
| 경로 | `/wiki` — 한 장. 자리마다 앵커(`#capture` · `#classify` · `#query` · `#insight`) |
| 부르는 곳 | 없다. `api`도 `agent`도 부르지 않는다 |
| 들어오는 길 | 상단 바 오른쪽 끝 "AI 위키", 그리고 화면 곳곳의 AI 표시 |

AI 자리 목록은 코드 한 곳(`interfaces/ai_map`)에 있고, 화면의 AI 표시와 위키의 표가
그 목록 하나를 같이 읽는다. 표시와 위키가 서로 다른 말을 하지 않게 하려는 것이다.

## 3. 화면 구조

| 영역 | 내용 |
|---|---|
| 머리 | 지금 AI가 붙어 있는지 — 진짜 agent가 선 자리를 이름으로 말하고, 나머지는 각본 대역이라고 한다 |
| 한눈에 | 자리 표 — 화면, 흐름, LLM 호출 수, 도구 모드, 지금 무엇이 서 있나 |
| 구조 | `ui` → `agent` → `api` 그림과 서비스별로 LLM을 아는지 |
| 에이전트 흐름 셋 | 단발 · ReAct · plan-and-execute, 고르는 기준 한 줄 |
| 자리별 | 대신하는 판단, 흐름의 단계, 도구, 사람이 끼는 자리, 못 할 때 |
| 원칙 | `docs/ai` 2장의 여덟 줄 |
| 도구 | 읽기·쓰기 카탈로그, 자리마다 좁히는 모드 |
| MCP | 외부 AI 서비스가 들어오는 통로. 기본은 꺼짐 |

## 4. 상호작용

정적인 한 장이다. 앵커 이동 말고는 아무것도 갱신되지 않는다.

화면의 AI 표시는 `AI · 흐름` 모양이다 — `AI · 단발`, `AI · ReAct`, `AI · 계획 실행`.
누르면 위키의 그 자리로 간다. 마우스를 올리면 기능 이름과 "지금은 각본 대역"이 보인다.

## 5. 빈 상태·로딩·에러

빈 상태가 없다. 대역 모드가 아니면 머리의 문구만 바뀐다.

## 6. 결정과 이유

- **화면 안에 둔다.** 저장소 문서로 링크를 걸면 쓰는 사람에게는 닫힌 길이다.
- **AI 자리 목록을 코드에 둔다.** 표시와 위키가 같은 목록을 읽어야 한쪽만 바뀌는 일이 없다.
  위키의 설명 글은 템플릿에 두고, 목록에 든 것은 자리의 이름·흐름·도구처럼 표에 들어갈 것뿐이다.
- **표시는 흐름을 말한다.** "AI"만 달면 사용자는 무엇이 도는지 모른다. 흐름 이름 한 단어가
  "여기는 한 번 판단하고 끝난다"와 "여기는 여러 번 돈다"를 가른다.

## 7. 하지 않는 것

- 위키 편집. 고칠 것은 `docs/ai/`를 고치고 위키를 맞춘다.
- 검색, 여러 장.
- 실행 기록(`agent_runs`) 보기. 진짜 `agent`가 붙은 뒤에 정한다.
