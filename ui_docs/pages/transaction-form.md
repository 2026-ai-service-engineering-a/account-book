# 거래 폼 — 새로 넣기·고치기

## 1. 목적

정확히 넣는다. 영수증을 보며 여러 건을 입력하거나, 금액이 커서 한 번 더 확인하고 싶거나,
에이전트가 잘못 넣은 것을 고칠 때 쓰는 화면이다. [채팅](chat.md)과 대등한 입력 경로이지
보조가 아니다.

## 2. 라우트와 데이터

| 경로 | 하는 일 | 부르는 곳 |
|---|---|---|
| `/transactions/new` | 새로 넣기 | `POST /v1/transactions` |
| `/transactions/{id}` | 고치기·지우기 | `PATCH` · `DELETE /v1/transactions/{id}` |

둘은 **같은 폼**이다. 값이 채워져 있느냐만 다르다.

카테고리의 AI로 고르기는 `agent`의 `POST /classify`를 부른다. 조회가 아니라 판단이라서다
(4.1, [../../docs/ai/category-suggestion-rag.md 3장](../../docs/ai/category-suggestion-rag.md#3-흐름--네-단계로-값이-싼-순서대로)).

## 3. 화면 구조 — 필드와 순서

| 순서 | 필드 | 기본값 | 비고 |
|---|---|---|---|
| 1 | **방향** | 지출 | 지출·수입 라디오. 가장 먼저 고른다 |
| 2 | 금액 | — | 정수 원. 천 단위 구분은 표시만, 전송은 정수 |
| 3 | 날짜·시각 | 지금 (사용자 타임존) | |
| 4 | 카테고리 | 방향에 따라 목록이 바뀐다 | |
| 5 | 결제수단 | 마지막에 쓴 것 | |
| 6 | 가맹점 | — | 선택. AI로 고르기의 재료가 된다 |
| 7 | 메모 | — | 선택 |

**방향을 가장 먼저 고르는 이유**는 카테고리 목록이 방향에 딸려 있기 때문이다.
지출 목록에 "급여"가, 수입 목록에 "식비"가 보이면 안 된다.

금액 입력은 모바일에서 숫자 키패드가 뜨게 한다. 가계부에서 가장 자주 누르는 칸이다.

## 4. 상호작용

| 무엇을 | 무엇이 갱신되나 |
|---|---|
| 방향 라디오 변경 | `#category-select` 하나만. 금액·날짜는 그대로 |
| 카테고리의 AI로 고르기 | `#category-select` 하나 — 선택값과 근거 한 줄 (4.1) |
| 한 줄 보내기 (붙여넣기·Enter) | `#transaction-form` 하나 — 읽은 칸과 말풍선 둘 (4.4) |
| 제출 | 페이지 이동 — 목록으로 |
| 삭제 | 확인 다이얼로그 → 목록으로 |

### 4.1 카테고리는 AI로 고르기를 누를 때만 고른다

카테고리 셀렉트 옆에 **AI로 고르기** 버튼이 있다. 누르면 `ui`가 가맹점·메모·방향을 `agent`의
`POST /classify`에 넘기고, `agent`가 지난 기록을 검색해 고른다 — 기능 1, RAG
([../../docs/ai/category-suggestion-rag.md](../../docs/ai/category-suggestion-rag.md)).
셀렉트 partial 하나만 갈아끼우고 금액·날짜는 건드리지 않는다.

- **누르기 전에는 아무것도 부르지 않는다.** 가맹점을 넣고 포커스를 옮겨도 고르지 않는다.
  타이핑하는 동안 자동으로 부르면 한 건 입력에 호출이 열 번 나고, 칸을 다 직접 채우는
  사람에게도 AI 호출이 생긴다.
- **누른 것이 동의다.** 이미 고른 카테고리도 바꾼다. 사용자가 다시 고르면 그 선택이 이긴다.
- **근거를 같이 보여 준다.** 셀렉트 아래에 한 줄 — "같은 가맹점 최근 5건 중 5건: 식비",
  "비슷한 기록: 메가커피 · 스타벅스 → 카페". LLM이 골랐으면 그 줄에 `AI` 표시가 붙는다.
  이유 없이 값이 바뀌면 사람이 검사할 방법이 없다.
- **못 고르면 셀렉트를 그대로 둔다.** "고를 만한 근거가 없어요"나 "지금은 추천할 수 없어요"를
  보여 주고, 사람이 고른다.

`POST /classify` — 요청은 `{merchant, memo, direction}`, 응답은
`{category_id, strategy, reason}`이다. `category_id`가 null이면 고르지 않았다. `strategy`는
`rule`·`history`·`vector`·`llm`·`none` 중 하나다. `agent`가 `api`에 닿지 못하면
`503` + `ledger_unavailable`, LLM에 닿지 못하면 `503` + `model_unavailable`.

### 4.2 제출이 곧 확인이다

폼 제출은 사용자가 모든 필드를 눈으로 보고 누른 것이다. 확인 카드를 또 띄우지 않는다.
`ui`가 `X-Confirmed-By: user`를 붙여 `api`를 직접 부른다.

`Idempotency-Key`는 **화면을 열 때** 만들어 숨은 필드에 둔다. 제출할 때 만들면
새로고침 후 재제출이 새 키를 받아 거래가 둘이 된다
([../../docs/api-contract.md 3장](../../docs/api-contract.md#3-멱등성--같은-거래가-두-번-들어가지-않게)).

### 4.4 한 줄로 채운다 — 카드 문자든 말이든

폼 맨 위에 **한 줄로 채우기** 칸을 둔다. 채팅처럼 한 줄을 보내면 AI가 읽어
방향·금액·날짜·결제수단·가맹점을 채우고, 가맹점을 읽었으면 `agent`가 4.1과 같은 방법으로
카테고리까지 골라 온다. 사용자가 이미 고른 카테고리는 덮지 않는다.
들어오는 한 줄은 두 가지다.

| 무엇을 | 예 | 어떻게 보내나 |
|---|---|---|
| 카드사 결제 문자 | `[Web발신] 신한카드(1234)승인 홍*동 8,500원 일시불 09/16 12:31 김밥천국` | 붙여넣으면 바로 |
| 말로 쓴 한 줄 | `오늘 오후 3시에 카페에서 5천원 썼어` | `Enter` 또는 채우기 버튼 |

영수증을 보며 넣는 사람에게 가장 흔한 원본은 카드사 문자고, 손에 문자가 없을 때는 말이 빠르다.
[채팅](chat.md)에서 기록하는 것과 같은 일이지만 여기서는 **확인 카드 대신 폼이 확인**이다 —
채워진 칸을 눈으로 보고 저장을 누른다. `docs/ai`가 "기록 (capture)"이라고 부르는 자리이고,
흐름은 단발이다([../../docs/ai/agent-loop.md 3장](../../docs/ai/agent-loop.md#3-어느-기능에-어느-흐름인가)).

칸은 채팅처럼 생겼다. 보낸 한 줄이 오른쪽 말풍선, 읽은 결과가 왼쪽 말풍선으로 남고
입력칸은 비워진다. 대화 기록을 쌓지는 않는다 — 마지막 한 번만 보인다. 폼을 채우는 일이지
대화가 목적이 아니다.

- **채우기까지만 한다.** 저장은 사용자가 누른다. 4.2의 "제출이 곧 확인"이 그대로 선다.
  AI가 조용히 돈 기록을 쓰는 길을 만들지 않는다([../../docs/ai/README.md](../../docs/ai/README.md) 2장 원칙 6).
- **채운 칸에 표시를 단다.** "AI가 채움" 표시가 사용자가 눈으로 확인할 곳을 알려 준다.
  표시 없이 채우면 사용자는 자기가 넣은 값과 구분하지 못한다.
- **읽은 칸만 덮는다.** 못 읽은 칸은 사용자가 이미 넣은 값을 그대로 둔다.
  보내기는 사용자가 채우라고 시킨 것이라, 읽은 칸은 기존 값을 덮는다 — 4.1과 다른 점이다.
- **못 읽으면 못 읽었다고 한다.** 금액을 못 찾았거나 승인 취소 문자면 아무 칸도 바꾸지 않고
  한 줄로 알린다. 그럴듯하게 채운 오답이 빈칸보다 비싸다(원칙 4).
- **보낸 문자열은 데이터다.** 그 안의 문장을 지시로 읽지 않고(원칙 5), 원문을 저장하지도
  메모로 옮기지도 않는다. 카드 문자에는 카드 번호 끝자리와 이름이 들어 있다.
- **AI가 없어도 폼은 돈다.** 이 칸은 가속기다. AI를 끄면 칸이 사라질 뿐 나머지는 그대로다(원칙 8).

`ui`는 문자를 해석하지 않는다. `agent`에 넘기고 구조화된 결과만 받는다
([../../docs/ai/README.md](../../docs/ai/README.md) 3장). 주고받는 모양은 4.5에 있다.
`AGENT_BASE_URL`이 비어 있으면 그 자리에 각본 대역이 선다([../stand-ins.md](../stand-ins.md)).

### 4.5 agent와 주고받는 것 — `POST /capture`

`agent`의 표면은 계약 문서에 없다. `ui`만 부르고, 이 절이
정본이다([../../docs/ai/README.md](../../docs/ai/README.md) 7.2).

```json
// 요청 — 기준 시각과 타임존은 ui가 준다. agent는 추측하지 않는다
{ "text": "오늘 오후 3시에 카페에서 5천원 썼어",
  "now": "2026-10-01T18:00:00+09:00", "timezone": "Asia/Seoul" }

// 응답 200 — 못 읽은 칸은 null. category는 가맹점을 읽었을 때만 있다(4.1과 같은 모양)
{ "direction": "expense", "amount": 5000, "occurred_at": "2026-10-01T15:00:00+09:00",
  "payment_method": null, "merchant": "카페", "refusal": "",
  "category": { "category_id": "cafe", "strategy": "vector",
                "reason": "비슷한 기록: 투썸플레이스 · 메가커피 · 스타벅스 → 카페" } }
```

| 무엇이 | 어떻게 |
|---|---|
| LLM이 정하는 것 | 금액, 방향, 결제수단, 가맹점, 날짜를 **말한 방식**(오늘·어제·월/일)과 시각. 단발, 1회. 이어서 카테고리(4.1) — 0~1회 |
| 코드가 정하는 것 | 실제 날짜. "어제"와 "09/16"의 연도를 `now`·`timezone`으로 계산한다(원칙 2) |
| 버리는 것 | 보낸 글에 없는 가맹점명(지어낸 것), 범위 밖 금액. 그 칸만 비운다 |
| 읽지 않기로 한 것 | 질문, 승인 취소 문자, 금액이 없는 글 — `refusal`에 사람에게 보일 한 줄이 온다. 상태는 200이다 |
| 스키마를 못 맞추면 | agent가 한 번 다시 시키고, 또 틀리면 `refusal` |
| 제공자에 닿지 못하면 | `503` + `model_unavailable`. ui는 "지금은 AI가 읽을 수 없어요"를 띄우고 칸을 그대로 둔다 |
| 카테고리만 못 고르면 | 읽은 값은 그대로 오고 `category.category_id`만 null이다. 카테고리 칸만 빈다 |

보낸 한 줄은 LLM 제공자에게 간다. 카드 문자라면 이름과 카드 끝자리도 함께다. agent는 그
원문을 저장하지 않고 운영 로그에도 남기지 않는다([../../docs/development-rules.md 6.4](../../docs/development-rules.md#64-로깅--운영-로그와-감사-로그를-나눈다)).

### 4.3 삭제만 다르다

삭제는 되돌릴 수 없다. 별도 확인을 묻고, 문구에 **금액과 가맹점을 다시 보여준다.**
"정말 삭제할까요?"만으로는 무엇을 지우는지 모른다.

## 5. 빈 상태·로딩·에러

**빈 상태** — 새 거래 화면은 늘 비어 있는 게 정상이다. 대신 방향·날짜·결제수단에
기본값이 차 있어서, 금액과 카테고리만 넣으면 끝나야 한다.

**로딩** — 제출 버튼을 누르면 잠근다. 두 번 눌러도 요청은 하나다.

**검증 실패** — 폼의 필수값·숫자 검사는 화면 편의일 뿐이다. 진짜 검증은 `api`가 한다.
`validation_error`의 `details`를 받아 **해당 필드 옆에만** 표시하고, 나머지 입력값은
그대로 둔다. 폼 전체를 다시 그리면 사용자가 쓴 것이 날아간다.

**예산 초과** — `budget_exceeded`는 저장을 막지 않는다. 저장한 뒤 목록에서 경고 배너로
알린다. 예산을 넘겨 쓸 자유는 사용자에게 있다.

## 6. 결정과 이유

- **새로 넣기와 고치기를 한 폼으로 둔다.** 필드가 같은데 화면을 둘로 만들면 규칙도
  둘이 된다. 하나가 바뀌면 다른 하나를 잊는다.
- **`Idempotency-Key`를 화면 열 때 만든다.** 제출 시점에 만들면 멱등성이 아무 의미가 없다.
- **카테고리는 버튼을 눌러야 고른다.** 처음에는 가맹점을 넣으면 자동으로 채웠다. 진짜 LLM이
  붙으면서 바꿨다 — 비용과 통제 둘 다다. 누르는 행위가 "AI가 값을 바꿔도 된다"는 동의가
  되고, 직접 다 넣는 사람에게는 AI 호출이 0번이다
  ([../../docs/ai/category-suggestion-rag.md 10장](../../docs/ai/category-suggestion-rag.md#10-결정과-이유)).
- **한 줄로 채우기는 버튼 없이 카테고리까지 채운다.** 보낸 것 자체가 채워 달라는 요청이라서다.
  그래도 사용자가 이미 고른 카테고리는 덮지 않는다.

## 7. 하지 않는 것

- 반복 거래(매달 자동 등록). 규칙 편집 화면이 따로 필요하다.
- 한 결제를 여러 카테고리로 쪼개기.
- 첨부 파일·영수증 사진.
