# 문서 화면

## 1. 목적

가계부를 보다 생긴 질문 — "할부로 산 걸 며칠 안에 취소할 수 있지?" — 의 근거 조문을 찾는다.
지금은 법령 사이트에서 법령을 고르고, 조문을 열고, 항을 끝까지 읽는다. 이 화면은 카드·할부·
전자금융·연말정산에 관한 법령 아홉 조문에서 그 항을 찾아 **원문 그대로** 보인다.

두 가지를 한다. **찾기**는 조문을 그대로 보인다 — `agent`가 붙어 있으면 뜻으로도 찾는다("AI 검색").
**묻기**는 찾은 조문을 인용해 한두 문장으로 답한다("AI 답"). 답에는 근거 조문이 붙고, 원문은 펼쳐 본다.
설계는 [../../docs/ai/document-rag.md](../../docs/ai/document-rag.md)다.

## 2. 라우트와 데이터

| | |
|---|---|
| 경로 | `/documents?q=&strategy=&mode=&action=` — GET 폼 하나. `action`은 `search`(기본)·`ask`. 주소에 질문이 남는다 |
| 부르는 곳 | `AGENT_BASE_URL`이 있으면 `agent` — `POST /retrieve`(`k`는 `DOC_TOP_K`). 없으면 `api` — `GET /v1/documents/search`(`k`는 5) |
| 묻기 | `agent`가 있으면 `POST /ask`(찾는 방법은 agent의 기본값). 없으면 각본 대역 — 낱말로 찾은 조문만 |
| 모델 | 찾기는 임베딩만. 묻기는 임베딩 + 생성 한 번 |

자료는 `api`에 `make docs`로 넣는다. `API_BASE_URL`이 비면 조문 네 줄짜리 대역이
선다([../stand-ins.md](../stand-ins.md) 2장).

## 3. 화면 구조

| 영역 | 내용 |
|---|---|
| 머리 | 제목과 한 줄 — 어느 자료에서 찾는지. `agent`가 있으면 "AI 검색" 표시, 없으면 낱말로만 찾는다는 것 |
| 찾기 | 질문 칸, 조각 나누기(항 단위 · 항이되 긴 항은 호 단위 · 500자씩), `agent`가 있으면 찾는 방법(낱말 · 뜻 · 둘 다), 찾기 · 묻기 버튼 |
| 답(묻기) | "AI 답" 표시, 답 한두 문장, 근거 조문 — 접힌 칸을 펼치면 원문. 그 아래 찾은 조문 전부(접혀 있다) |
| 결과 | 카드(`agent`가 있으면 여덟 장, 없으면 다섯 장) — 법령명과 조·항, 점수, 원문 인용, 시행일자와 조각 id |
| 끝 | "조문을 옮긴 것이고 법률 자문이 아닙니다" — 결과가 있을 때 늘 |

인용은 원문이다. 개정 꼬리표(`<개정 …>`)도 그대로 보인다 — 찾을 때만 뺀다.

## 4. 상호작용

- 찾기를 누르면 페이지 전체가 새로 그려진다. 부분 갱신을 두지 않는다 — 결과가 곧 화면 전부다.
- 조각 나누기를 바꿔 같은 질문으로 다시 찾으면 결과가 달라진다. 셋을 견주는 것이 이 화면의
  두 번째 쓰임이다(청킹 학습, 이슈 #11).
- 기본은 재서 고른 값이다(document-rag.md 6.3·7.2) — 나누기는 "항 · 긴 항은 호", `agent`가 있으면 찾는
  방법은 "둘 다(하이브리드)", 조각 수는 `agent`의 `DOC_TOP_K`(8). `agent`가 없으면 방법 고르기가 보이지 않고
  낱말로 다섯 장을 찾는다. 모르는 값이 주소에 오면 기본으로 찾는다.

## 5. 빈 상태·로딩·에러

**빈 상태** — 질문이 없으면 조문의 낱말로 찾으라고 알린다. "헬스장"보다 "체력단련장",
"카드값 공제"보다 "신용카드등사용금액". 키워드 검색이 사람의 말에 약하다는 것을 숨기지 않는다.

**결과 없음** — "찾은 조각이 없어요". 키워드 검색은 점수로 거르지 않아서 자료가 들어 있으면 늘
다섯 장이 나온다 — 이 줄은 `make docs`를 하지 않은 DB에서 보인다.

**물러섬** — 뜻으로 찾기를 골랐는데 `agent`나 임베딩 제공자에 닿지 못하면 낱말로 찾고 "지금은 뜻으로 찾을
수 없어 낱말로 찾았어요"를 띄운다. 화면은 멈추지 않는다(docs/ai 원칙 8).

**묻기의 세 끝** — 답했다(답 + 근거), 근거가 없다("이 조문들에는 근거가 없어요"와 가장 가까운 조문),
답 대신 찾은 조문만(생성·검증이 실패했거나 `agent`에 닿지 못했다 — 까닭 한 줄). 어느 끝이든 찾은 조문은
펼쳐 볼 수 있다. 답은 근거 조문의 id와 숫자를 검증한 것만 보인다(document-rag.md 5.3).

**에러** — `api`에 닿지 못하면 다른 화면과 같은 에러 페이지.

## 6. 결정과 이유

- **GET 폼이다.** 주소에 질문과 나누기가 남아서 결과를 공유하고 뒤로 가기로 돌아온다. 검색 화면에
  상태를 숨길 이유가 없다.
- **점수를 보인다.** 사용자에게는 군더더기지만, 지금 이 화면의 다른 쓰임이 검색을 재는 것이다.
  답을 만드는 단계(doc-qa)가 붙으면 다시 정한다.
- **인용 아래에 시행일자.** 법이 바뀌면 답이 바뀐다. 언제의 조문인지 늘 보인다.

## 7. 하지 않는 것

- 문서 올리기 — 받아 둔 법령만 넣는다(document-rag.md 7.1).
- 조문 전체 보기·법령 사이트 링크.
